אפליקציית חשבונאות רשת מלאה מבוססת רישום כפול — **נוסחה כולה על ידי בינה מלאכותית**, מהארכיטקטורה ועד הקוד ועד הבדיקות.

## מהו הפרויקט הזה?

מאגר זה מכיל אפליקציית חשבונאות שנבנתה ב-Python. האפליקציה מיישמת ליבת רישום כפול אמיתית — לו״ח חשבונות, פקודות יומן, הפנקס הכללי, מאזן בוחן, דוח רווח והפסד ומאזן — בנוסף על הוצאת חשבוניות, חשבונות חייבים וזכאים, תקציבים וייצוא דוחות ב-CSV/PDF, הכול זמין דרך ממשק רשת.

אך האפליקציה עצמה אינה הנקודה המרכזית. **הנקודה המרכזית היא שכל האפליקציה נוסחה על ידי בינה מלאכותית.** אף אדם לא כתב אפילו שורת קוד אחת בפרויקט הזה. הבינה המלאכותית תכננה את הארכיטקטורה, כתבה את הבק-אנד, את הפרונט-אנד, את הבדיקות ואת התיעוד. [AI_WORKFLOW.md](AI_WORKFLOW.md) הוא הרשומה המלאה של האופן שבו הבינה המלאכותית בנתה אותו, שלב אחר שלב.

## המטרה

להדגים ש**מודל בינה מלאכותית מקומי עם משקולות פתוחות, הרץ על עמדת עבודה אחת בלבד לשימוש צרכני** יכול לייצר פרויקט תוכנה שלם, עקבי ועובד — לא קטע קוד, לא צעצוע, אלא אפליקציה אמיתית עם בסיס נתונים, REST API, ממשק רשת, בדיקות אוטומטיות ותיעוד.

## למה נוצר?

- להראות מהי יכולתם של מודלי LLM מקומיים במהנדסי תוכנה מקצה לקצה.
- להוכיח שקידוד עם בינה מלאכותית מתקדמת כבר אינו דורש API ענן — מודל של 27 מיליארד פרמטרים על עמדת עבודה ניידת ברמת לפטופ מספיק לבניית אפליקציה שלמה.
- כדוגמה ציבורית שניתן לאמת: היסטוריית ה-git המלאה מציגה בינה מלאכותית המחברת את הפרויקט צעד אחר צעד.

## סקירה כללית

חשבונאות היא מערכת רישום כפול שלמה לעסק קטן. היא מכסה את מחזור החשבונאות המלא: הקמת לו״ח חשבונות, רישום פקודות יומן, מעקב אחר הפנקס הכללי, יצירת דוחות כספיים, הוצאת חשבוניות ללקוחות ותשלום פקטורות ספקים, תכנון תקציבים, התאמת פקודות בנק וייצוא דוחות ב-CSV או ב-PDF. הכול זמין דרך ממשק רשת, REST API ושרת [MCP](https://modelcontextprotocol.io) שאפשר לבינה מלאכותית לשאול את החשבונות.

במצפון, האפליקציה כוללת:

- **ליבת רישום כפול** — לו״ח חשבונות, פקודות יומן, הפנקס הכללי, מאזן בוחן
- **דוחות כספיים** — דוח רווח והפסד ומאזן (נכסים = חובות + הון עצמי, מבחינת הבנייה)
- **חשבוניות וחשבונות חייבים** — נורמת מס שטוחה, תשלומים, תשלומים חלקיים, ביטולים
- **הצעות מחיר** — הצעות שהופכות לחשבוניות בשלב אחד
- **פקטורות וחשבונות זכאים** — חשבון הוצאה לכל שורה, מס זכאי להחזר, תשלומים, ביטולים
- **תקציבים** — מתוכנן מול בפועל עם סטייה, על פני טווחי תאריכים מותאמים אישית
- **התאמת בנק** — נעילת שורות שהוסדרו וכלל ההפרש הקלאסי
- **ייצוא** — 7 דוחות ב-CSV וב-PDF
- **הזדהות** — משתמש יחיד, הגדרה בריצה הראשונה, מפגשי cookie חתומים
- **ממשק רשת** — SPA ב-JS טהור ללא שלב בנייה
- **נתוני הדגמה** — עסק דוגמה שלם ומאוזן דרך `--seed`
- **שרת MCP** — כל עוזר בינה מלאכותית יכול לשאול את החשבונות (ולרשום עסקאות, לפי בחירה) דרך 19 כלים שנבחרו בקפידה, דרך stdio או streamable HTTP

## תכונות

### ליבת הרישום הכפול

היסוד הוא מנוע רישום כפול אמיתי. לו״ח חשבונות סטנדרטי של 26 חשבונות נטען אוטומטית בריצה הראשונה, וכל אירוע כספי — רישומים ידניים, חשבוניות, תשלומים, פקטורות — עובר דרך מסלול יומן יחיד שמדחה כל פקודה שבה סך החובה אינו שווה לסך הזכות. ביטולים הם פקודות הפוכות, לעולם לא מחיקות, ולכן היסטוריית החשבונות המלאה נשמרת. מעל היומן עומדים הפנקס הכללי (פעילות לכל חשבון, עם יתרת פתיחה ויתרה רצה) ומאזן הבוחן (כל חשבון בעמודת החובה או הזכות הטבעית שלו).

*מקרה שימוש:* רשמו השקת בעלים של 5,000$ (חובה: מזומנים, זכות: הון בעלים); כשתבינו שהסכום היה שגוי, בטלו אותו — נרשמת פקודה הפוכה, הפקודה המקורית נשארת בהיסטוריה והחשבונות נשארים מאוזנים.

### דוחות כספיים

דוח רווח והפסד מדווח על ההכנסות מול ההוצאות לכל תקופה, יחד עם הרווח הנטו הנובע מהן. המאזן מדווח על נכסים, חובות והון עצמי כנכון לתאריך — ומכיוון שההון העצמי כולל את כלל הרווח הנטו מכל הזמנים, נכסים = חובות + הון עצמי נכון מבחינת הבנייה, ולא במקרה.

*מקרה שימוש:* בדקו את הרווח של החודש בדוח רווח והפסד, ואז חפשו את השווי הנטו של החברה כנכון להיום במאזן.

### חשבוניות וחשבונות חייבים

נהלו לקוחות וקטלוג פריטים, ואז בנו חשבוניות משורות (כמות × מחיר יחידה, הסכומים נחשבים בשרת, שמות הפריטים מתועתקים לשורה כך ששינויי פריטים מאוחרים לעולם לא יכתבו מחדש את ההיסטוריה). נורמת מס שטוחה חלה על כל חשבונית. רשמו תשלומים — כולל תשלומים חלקיים — ומצב החשבונית (פתוחה, שולמה חלקית, שולמה, בטלה) נגזר אוטומטית. חשבוניות ניתן לבטל כל עוד הן טרם שולמו.

*מקרה שימוש:* הוציאו חשבונית ללקוח על 3 פריטים בנורמת מס של 10%, קבלו תשלום חלקי השבוע ואת יתרת הסכום בחודש הבא — המצב מתעדכן לבדו בכל שלב.

### הצעות מחיר

צרו הצעות מחיר שאינן רושמות דבר בפנקס. כשלקוח מקבל, הופכים את ההצעה לחשבונית בשלב אחד; ההצעה מסומנת אז כהופכת ואינה ניתנת להמרה שוב.

*מקרה שימוש:* שלחו הצעת מחיר לפרויקט; הלקוח מאשר אותה שבוע מאוחר יותר — הופכים אותה לחשבונית בלחיצה אחת והחשבונות ממשיכים מכאן.

### פקטורות וחשבונות זכאים

נהלו ספקים ורשמו פקטורות עם חשבון הוצאה לכל שורה: כל שורה נרשמת לחשבון ההוצאה שבחרתם (מתוקן כחשבון הוצאה פעיל), עם מעקב נפרד אחרי המס הזכאי להחזר. שלמו פקטורות ממזומנים, או בטלו אותן כל עוד הן טרם שולמו.

*מקרה שימוש:* רשמו פקטורת חשמל של 500$ לחשבון הוצאות שירותים ושלמו ממזומנים — גם ההוצאה וגם יציאת המזומנים מתועדות בתהליך אחד.

### תקציבים

קבעו סכום מתוכנן לכל חשבון על פני כל טווח תאריכים מותאם אישית. דוח התקציבים משווה כל תקציב לפעילות בפועל בטווח שלו עצמו, ומציג את הסטייה ואת השאלה האם החשבון נמצא בתוך התקציב.

*מקרה שימוש:* תקצבו 2,000$ לחודש לשיווק; הדוח מראה שהוצאתם 1,450$ — 550$ מתחת לתקציב.

### התאמת בנק

סמנו חשבונות כחשבונות בנק, ואז תאמו פקודת בנק (תאריך + יתרת סיום) מול שורות היומן. שורות תואמות ננעלות כ"הוסדרו", וכלל ההפרש הקלאסי — יתרת פתיחה ועליה פעילות שהוסדרה מול יתרת הפקודה — מראה בדיוק עד כמה יש פער בחשבונות. מחיקת התאמה משחררת את שורותיה, ורישומים בעלי שורות שהוסדרו אינם ניתנים לביטול.

*מקרה שימוש:* פקודת הבנק שלכם מסתיימת ב-12,345.67$; בחרו את העסקאות התואמות והאפליקציה מציגה הפרש של 0$ — או מציינת את הסכום המדויק שאינו מתאים.

### ייצוא

שבעה דוחות — הפנקס הכללי, מאזן בוחן, דוח רווח והפסד, מאזן, יומן, חשבוניות ופקטורות — ניתנים להורדה כ-CSV או כ-PDF, עם מסנני טווח תאריכים וחשבונות במקומות הרלוונטיים. סכומים מוצגים בדולרים עם שני ספרות אחרי הנקודה.

*מקרה שימוש:* ייצאו את דוח רווח והפסד כ-PDF להגשה לרואה החשבון שלכם, או את היומן כ-CSV לניתוח בגיליון נתונים.

### הזדהות

הזדהות של משתמש יחיד: הביקור הראשון מציג מסך הגדרה ליצירת החשבון, ואז כל בקשה מוגנת על ידי מפגש cookie חתום ו-HttpOnly עם אורך חיים של 12 שעות.

*מקרה שימוש:* פתחו את האפליקציה בפעם הראשונה, צרו חשבון במסך ההגדרה ונשארו מחוברים במשך 12 שעות בלי להזין שוב את הסיסמה.

### ממשק רשת

SPA ב-JavaScript טהור ללא שלב בנייה: 12 דפים המכסים כל תכונה, בנוסף על דשבורד עם כרטיסיות למזומנים, חשבונות חייבים, חשבונות זכאים ורווח נטו מצטבר, לצד פקודות היומן האחרונות.

*מקרה שימוש:* פתחו את האפליקציה ועברו מבט על הדשבורד כדי לראות את מצב המזומנים ואת הפעילות האחרונה לפני שצוללים לכל דף.

### נתוני הדגמה

`python main.py --seed` מטעין עסק דוגמה שלם ומאוזן — לקוחות, ספקים, פריטים, חשבוניות המכסות כל מצב, פקטורות, תקציבים והתאמת מזומנים מאוזנת — כך שהאפליקציה מציגה את עצמה היטב כבר בריצה הראשונה. היכנסו כ-`demo` / `demo123`.

*מקרה שימוש:* הרצו את האפליקציה עם `--seed` וגלו עסק ריאלי בפקודה אחת, ללא הגדרה ידנית.

### שרת MCP

האפליקציה מגיעה עם שרת [Model Context Protocol (MCP)](https://modelcontextprotocol.io) עם 19 כלים שנבחרו בקפידה (12 לקריאה, 7 לכתיבה לפי בחירה), 2 משאבים ו-3 פרומפטים, דרך stdio או streamable HTTP — כך שכל עוזר בינה מלאכותית יכול לשאול את החשבונות ולרשום עסקאות, לפי בחירה.

*מקרה שימוש:* שאלו Qwen מקומי ב-LM Studio "אילו חשבוניות פגו תוקפן?" וקבלו תשובה עם מספרים אמיתיים מהחשבונות. ההגדרה המלאה ב[הסעיף הבא](#שימוש-עם-בינה-מלאכותית-mcp).

## שימוש עם בינה מלאכותית (MCP)

האפליקציה מגיעה עם שרת [Model Context Protocol (MCP)](https://modelcontextprotocol.io), ולכן **כל עוזר בינה מלאכותית** — ChatGPT, Claude או Qwen מקומי ב-LM Studio — יכול להפעיל אותה כמו רואה חשבון. שאלו באנגלית פשוטה — *"כמה עמד השכרול במרץ?"*, *"כמה מס חייבים?"*, *"אילו חשבוניות פגו תוקפן?"* — והבינה המלאכותית קוראת לכלים עם סוגים ומענה עם מספרים אמיתיים מהחשבונות, או (לפי בחירה) רושמת עסקה בשמכם.

השרת חושף **19 כלים שנבחרו בקפידה, המבוססים על כוונה** — במתכוון לא מעבר גולמי של API, כי מחקר על שרתי MCP לחשבונאות (שרת QuickBooks של Intuit עם 145 כלים מול ~29 כלים שנבחרו בקפידה בשרתי Xero ובשרתי הקהילה) מראה שכלים שנבחרו בקפידה אמינים בהרבה עבור מודלי LLM:

- **12 כלים לקריאה, תמיד פעילים**: לו״ח חשבונות, דוח רווח והפסד, מאזן, מאזן בוחן, פנקס לכל חשבון, חיפוש טקסט חופשי בעסקאות, חשבוניות, פקטורות, הצעות מחיר, דוח תקציבים, התאמות בנק.
- **7 כלים לכתיבה, לפי בחירה** (קבעו `MCP_ALLOW_WRITE=1`): פקודות יומן, חשבוניות, תשלומי חשבוניות, ביטול חשבוניות, פקטורות, תשלומי פקטורות, תקציבים. כל כתיבה עוברת את אותו מסלול רישום יחיד כמו באפליקציית הרשת, ולכן החשבונות מאוזנים מבחינת הבנייה.
- **2 משאבים**: לו״ח החשבונות ומאזן הבוחן הנוכחי, זמינים למודל כהקשר קבוע.
- **3 פרומפטים** (פקודות slash באלקליינטים כמו Claude): `/monthly_report`, `/tax_position`, `/cash_position`.

תוצאת כל כלי כוללת גם סנטים במספרים שלמים וגם מחרוזת USD מסוננת, כך שאפילו מודלים מקומיים קטנים יכולים לצטט מספרים מדויקים. שגיאות חוזרות כשגיאות כלי קריאות (למשל *"Account 'Payroll' not found. Valid accounts: ..."*) שהמודל יכול להתאושש מהן, ולא כקריסות.

### הרצת שרת MCP

```bash
python mcp_server.py            # stdio transport (default) — for local clients
MCP_HTTP_TOKEN=your-secret python mcp_server.py --http   # streamable HTTP — for remote clients
```

מצב HTTP נקשר ל-`127.0.0.1:8765` (שינוי דרך `--host` / `--port`) ומסרב להתחל בלי טוקן ה-bearer `MCP_HTTP_TOKEN` — נתונים כספיים מקבלים הזדהות מחמירה יותר מהברירת המחדל loopback ללא הזדהות שמגיעה עם שרתי MCP אחרים.

| `ACCOUNTING_DB_PATH` | קובץ SQLite לפתיחה (ברירת מחדל: `accounting.db` בשורש הפרויקט — אותו קובץ שבו משתמשת אפליקציית הרשת; מצב WAL הופך גישה מקבילה לבטוחה) |
| `MCP_ALLOW_WRITE` | קבעו `1` להרשמת 7 כלים לכתיבה (ברירת מחדל: לקריאה בלבד) |
| `MCP_HTTP_TOKEN` | טוקן bearer הנדרש למצב `--http` |

### חיבור של אלקליינט

`python mcp_server.py --print-config <client>` מדפיס תצורה מוכנה להדבקה עבור `lmstudio`, `claude-code`, `claude-desktop`, `cursor`, `ollmcp`, `qwen-code` או `opencode` (הוסיפו `--http` לגרסת URL מרוחקת + כותרת bearer):

- **LM Studio** (Qwen מקומי): הדביקו את רשומת `mcpServers` בהגדרות ה-MCP של LM Studio — אז Qwen מקומי יכול לשאול את החשבונות ישירות.
- **Claude Desktop / Claude Code / Cursor / Qwen Code**: הדביקו את רשומת `mcpServers` בקובץ תצורת ה-MCP של האלקליינט.
- **Ollama**: Ollama הוא שרת מודלים, לא אלקליינט MCP — השתמשו בפקודת הגשר שהוא מדפיס (`ollmcp mcp add accounting -- ...`), או הכוונו Cline / opencode אל Ollama כבאק-אנד מודלים.
- **ChatGPT / OpenAI Agents SDK / Anthropic Messages API**: הרצו `--http` והכוונו את המחבר המרוחק אל `http://127.0.0.1:8765/mcp` עם טוקן ה-bearer.
- **ניפוי באגים**: אלקליינט הניפוי הסטנדרטי הוא [MCP Inspector](https://github.com/modelcontextprotocol/inspector) (`npx @modelcontextprotocol/inspector`), או `mcp dev mcp_server.py` עם תוספת ה-CLI של ה-SDK.

הנימוק העיצובי — כלים שנבחרו בקפידה מול מעבר API, שיטור כתיבה, הזדהות בטוקן, קטלוג הכלים — מתועד ב-[AIHelper.md](AIHelper.md) (סעיף "MCP server").
